# CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tự động kiểm tra cài package và hồi quy trên GitHub cho pull request và nhánh main.

**Architecture:** Một workflow GitHub Actions với bốn job matrix độc lập.
Cài package editable, kiểm tra entry point, chạy pytest và lưu báo cáo của từng job.

**Tech Stack:** GitHub Actions, Python 3.10/3.11, pip, pytest, pytest-cov có sẵn trong nhóm dev.

**Spec:** `docs/superpowers/specs/2026-10-28-ci-design.md`

## Global Constraints

- Runner: `ubuntu-latest`, `windows-latest`; Python: `3.10`, `3.11`.
- Trigger: `pull_request` vào `main`, `push` vào `main`, và `workflow_dispatch`.
- Quyền token: `contents: read`; không cần secret hay dịch vụ ngoài.
- `fail-fast: false`; timeout mỗi job 10 phút.
- Coverage chỉ để quan sát; không có ngưỡng phần trăm bắt buộc.
- Không thêm dependency, không thay đổi logic ứng dụng hoặc nội dung test.
- Không triển khai CD, publish PyPI, build wheel/sdist, hoặc thay đổi branch protection.

## Review Focus

- Windows: shell phải hiểu đúng quoted extras và CLI entry point sau cài đặt.
- Python 3.10: dependency resolution và mã nguồn phải tương thích phiên bản tối thiểu.
- Test lỗi: pytest phải làm job đỏ; upload artifact vẫn chạy nếu có báo cáo.
- Bốn job song song: artifact không trùng tên; lỗi một job không hủy job khác.
- PR cập nhật liên tiếp: chỉ hủy run cũ cùng PR, không hủy run của PR khác.

## Task 1: Thêm workflow CI và hướng dẫn sử dụng

**Files:**
- Create: `.github/workflows/ci.yml` — toàn bộ pipeline.
- Modify: `README.md` — bổ sung mục CI sau phần chạy kiểm thử.
- Existing validation: toàn bộ `tests/`, không tạo test mô phỏng cấu hình YAML.

**Interfaces:**
- Consumes: `pyproject.toml` extra `dev`, entry point `zip-fingerprint`, bộ test hiện tại.
- Produces: check `test (<os>, <python>)` và artifact `test-reports-<os>-py<python>`.

- [x] **Step 1: Xác nhận baseline trước sửa**

  Đọc spec và kiểm tra `git status --short`. Trong môi trường triển khai đã cài
  `.[dev]`, chạy `python -m pytest`; baseline tham khảo là 33 passed.
  Nếu khác baseline, điều tra trước khi sửa, không tự sửa logic ứng dụng trong task CI.

- [x] **Step 2: Tạo `.github/workflows/ci.yml` theo spec**

  Đặt tên workflow `CI`, job `test`, job name
  `test (${{ matrix.os }}, ${{ matrix.python-version }})`.
  Dùng hai trục matrix như Global Constraints, Python version phải là chuỗi.
  Đặt `permissions: contents: read`, timeout 10 phút và `fail-fast: false`.
  Concurrency group là `${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}`,
  `cancel-in-progress: true`.

  Các bước job theo thứ tự:
  1. `actions/checkout@v5`, `persist-credentials: false`.
  2. `actions/setup-python@v6`, `python-version` lấy từ matrix,
     `cache: pip`, `cache-dependency-path: pyproject.toml`.
  3. `python -m pip install --upgrade pip`.
  4. `python -m pip install -e ".[dev]"`.
  5. `python -m pip check`.
  6. `zip-fingerprint --help`.
  7. `python -m pytest --cov=zip_fingerprint --cov-report=term-missing --cov-report=xml:coverage.xml --junitxml=junit.xml`.
  8. `actions/upload-artifact@v4`, điều kiện `if: ${{ !cancelled() }}`,
     tên `test-reports-${{ matrix.os }}-py${{ matrix.python-version }}`,
     hai đường dẫn `coverage.xml`, `junit.xml`, `retention-days: 7`,
     `if-no-files-found: warn` để lỗi cài đặt không bị báo lỗi artifact che khuất.

  Không dùng `continue-on-error`, `|| true`, coverage threshold, path filter,
  hoặc `pull_request_target`. Các version action trên đã được kiểm tra có tag;
  không yêu cầu đây là version mới nhất.

- [x] **Step 3: Cập nhật README**

  Mô tả trigger và bốn môi trường; chép đúng các lệnh cài đặt/kiểm tra ở Step 2.
  Chỉ rõ vị trí GitHub Actions → run → Artifacts và thời hạn 7 ngày.
  Ghi coverage chưa có ngưỡng; bốn test placeholder chưa xác thực các chức năng
  tương ứng. Không mô tả workflow xanh là đã hoàn tất tái hiện bài báo.

- [x] **Step 4: Kiểm chứng local**

  Trong môi trường triển khai, chạy các lệnh Step 2 từ cài package đến pytest.
  Kỳ vọng: `pip check` không có broken requirements; CLI hiển thị help với mã 0;
  pytest mã 0; hai file XML tồn tại và đọc được.
  Chạy `git diff --check` để kiểm tra whitespace.
  Nếu máy thiếu dependency/network, ghi rõ bước chưa chạy; không coi đó là kết quả pass.
  Đọc lại workflow để đối chiếu toàn bộ Review Focus và kiểm tra cú pháp bằng
  `actionlint` nếu có sẵn; không thêm tool vào dependency của ứng dụng.

- [ ] **Step 5: Kiểm chứng trên GitHub khi triển khai được đẩy lên**

  Mở PR vào `main` với quyền đẩy/mở PR của phiên triển khai. Kỳ vọng bốn job xanh,
  bốn artifact tên khác nhau chứa hai báo cáo. Trên nhánh thử của PR, tạm thêm
  `tests/test_ci_failure_probe.py` với `def test_ci_failure_probe(): assert False`;
  xác nhận job đỏ và vẫn có báo cáo, rồi xóa probe và xác nhận bốn job xanh lại.
  Không để probe trong thay đổi cuối cùng.
  Cập nhật nhánh thử hai lần để kiểm tra concurrency: run cũ cùng PR bị hủy,
  run mới tiếp tục; biểu thức group phải giữ PR khác độc lập.
  Nếu chưa đẩy lên GitHub, ghi bước này là chưa kiểm chứng, không tuyên bố CI đã xanh.

- [x] **Step 6: Hoàn tất thay đổi triển khai**

  Kiểm tra diff chỉ gồm workflow và tài liệu dự kiến; không có probe hay báo cáo XML.
  Commit đề xuất: `ci: test package on Ubuntu and Windows`.

- Pytest với coverage/JUnit: 33 passed, coverage 84%; cả hai XML đọc được.
- `git diff --check`: pass. Review độc lập: không có findings.
- `actionlint` không có sẵn; cú pháp workflow được review thủ công.

  kiểm chứng hoặc báo cáo sinh ra. Mã nguồn và test ứng dụng không thay đổi.
